# 行迹 xingji

给一份景点清单和几天假，排出一份走得完的行程，再让模型把它讲成人话。

分工很硬：**排程在本地算，一个字都不让模型碰；模型只负责讲，讲的时候不许新增地点、不许自己估数字。**

![演示](assets/demo.gif)

## 为什么不让模型排

我试过。把 14 个点、3 天时间、每天 540 分钟丢给模型，它排出来的东西是这样的：第 2 天 4 个点，上午在成华区看熊猫，中午去武侯区吃面，下午回青羊区看博物馆，晚上又去武侯区。通勤时间它压根没算——在它眼里，地图是平的。

本地排程至少要算四件事，这四件都有唯一答案：

| 算什么 | 怎么算 | 不算会怎样 |
| --- | --- | --- |
| 每天容量 | 各点时长 + 跨区通勤 40 分钟 + 午饭 60 分钟 ≤ 540 | 排出来的行程走不完 |
| 闭馆日 | 清单里的「周一休」按 weekday 过滤 | 周一到博物馆门口看见闭馆通知 |
| 区域聚合 | 同区域连着排，跨区才收 40 分钟 | 一天来回横穿城区 |
| 预算 | 门票累加，超过就换下一个 | 到了售票口才发现超支 |

模型干不了这些，因为它不知道 40 分钟是我定的假设，也不知道地铁换乘要多久。它能干的只有一件：把「为什么这么排」说清楚。

## 真的跑了一遍

清单是 `samples/成都景点.txt`，14 个点（虚构的示例数据，时长和门票是大概口径）。3 天，每天 540 分钟，预算 900，第 1 天按周一起算，必去大熊猫基地和武侯祠。

排出来 10 个点，4 个进不去：

```
第 3 天（周三）· 成华区 / 武侯区 / 青羊区 · 470 分钟 · 70 元

```

大熊猫基地排到 09:00 第一件事，是因为清单里写着「上午最活跃，越早越好」。**这是被修出来的**——第一版按区域排序，它被排到 11:40，到那儿熊猫已经吃饱睡下了。排序现在看三样：必去、时段、区域。

四川博物院排在周二，因为它「周一休」，而第 1 天恰好是周一。

然后让模型讲：

```
第 1 天 · 熊猫要趁早，下午逛园林
上午先冲大熊猫繁育研究基地，越早到越好，熊猫上午最活跃。下午杜甫草堂园林大，
慢慢走不赶。傍晚大慈寺在闹市里，免费进去转一圈就收工。今天门票一共 105 元。

第 2 天 · 红墙竹影配盖碗茶
武侯祠红墙竹影，建议早去。四川博物院免费但周一闭馆，今天是周二没问题。
人民公园鹤鸣茶社喝盖碗茶歇歇。青羊宫收尾，道观安静。门票合计 70 元。

提醒：
  · 春熙路、太古里、成都博物馆、宽窄巷子这次没排进去，每天时间塞满了，下次再补。
  · 四川博物院周一闭馆，行程安排在周二，别记错日子。
```

每个数字都对得上：105 元是第 1 天门票合计，70 元是第 2 天合计，210 分钟是熊猫基地的时长。它没编。

## 核验：两次真实的翻车

**第一次：抓出四条假地名，全是我的正则闯的祸。**

第一版用「以地名后缀结尾的中文片段」来抓，后缀里带了「馆」「寺」「里」这些单字。跑完报了四条：

- `闹市里的寺` —— 来自备注「闹市里的寺院」
- `注意周一闭馆` —— 「闭馆」里有个「馆」
- `老厂房改的园区` —— 「园区」是后缀，前面全是修饰语
- `时长都按行程里` —— 「里」被当地名后缀

警告比正文还长，一条真的都没有。改法有三层：后缀只留两个字以上（单字后缀一律不要），候选里不许出现「的、在、要、去、来」这类虚词，并且**先把清单里的名字从文本里摘掉**再扫——否则「上午去武侯祠」会被从中间切开。

**第二次：跨标点粘连。**

修完还剩两条：`墙竹影+博物馆` 和 `天：金沙遗址`。都是标题里的字。原因是往前扩字时没检查字符类型，正则直接跨过 `+` 和 `：` 把上一句的尾巴粘了上来。加上「往前扩的每一段必须整段是中文」才干净。

现在 0 个。

**数字核验**是另一套：带单位的数字（元、分钟、小时）必须落在行程里真实出现过的集合里。第一次跑时「今天门票一共 105 元」被误报——105 是每天的门票合计，我只把单个点的票价放进了白名单，漏了每天的合计。补上之后 0 条。

距离（公里/千米）一律提醒：清单里根本没有距离数据，模型写出来就是编的。

## 快速开始

```bash
git clone https://github.com/wushiyi105-jpg/xingji.git && cd xingji
cp .env.example .env      # 填 LLM_API_KEY

python -m xingji import samples/成都景点.txt --destination 成都
python -m xingji plan --destination 成都 --days 3 --weekday 1 --must 大熊猫繁育研究基地,武侯祠
python -m xingji story 1        # 让模型讲一遍（要联网）
```

`plan` 不调模型，断网也能用；`story` 才需要 key。

起网页：

```bash
python -m xingji serve      # http://127.0.0.1:8776
```

## 清单格式

一行一个点，竖线分隔：

```
名称 | 区域 | 建议时长(分钟) | 门票(元) | 开放日 | 最佳时段 | 必去 | 备注
武侯祠 | 武侯区 | 120 | 50 | 全周 | 上午 | 1 | 红墙竹影，建议早去
四川博物院 | 青羊区 | 180 | 免费 | 周一休 | 上午 | 0 | 周一闭馆，别白跑
```

开放日认这些写法：`全周`、`周一休`、`逢周一闭馆`、`周二至周日`、`周一,周三`、`1,2`。

时段只认 `上午`、`下午`、`全天`，用来决定同一天里的先后。

## 命令

| 命令 | 做什么 |
| --- | --- |
| `import <文件> [--destination]` | 导入清单，同一目的地整份替换 |
| `plan --destination X [--days] [--minutes] [--weekday] [--must] [--budget]` | 排程，不调模型 |
| `story <id> [--prefs]` | 让模型把行程讲一遍，并核验 |
| `list` / `show <id>` / `rm <id>` / `stats` / `serve` | 管理、查看、网页 |

`--weekday` 是第 1 天是周几：周日 0，周一 1（默认）。这个编号跟清单里的 `open_days` 保持一致，两边错开过一次，导致「周一闭馆」的馆被排进了周一。

## 网页

左边填清单和参数，点「排一下」立刻出结果（本地算，秒回）。右边点「写解说」才发请求给模型。核验出来的问题用黄条标在文案下面，不藏。

## 设计取舍

- **零第三方依赖**，Python 3.10+ 标准库。
- **排不下的点不隐藏**。宁可告诉你「春熙路没排进去，因为每天时间满了」，也不要偷偷塞进去让你现场发现走不完。
- **通勤按固定 40 分钟**。真实情况差异很大，但一个假设比没有假设好；要改就改 `--travel`。
- **午饭固定 1 小时，插在两个点之间**，不插在景点中间。
- **同一目的地重新导入会整份替换**。改清单就该是新的，不留旧点。
- **行程与解说分开存**。解说重写不影响排程。

## 局限

- 清单得自己整理，没有地图数据，距离一律按「同区域 0、跨区域 40 分钟」估。
- 不处理营业时间（早 9 点前、晚 6 点后开放的点排不进去，会算成时间溢出）。
- 地名核验靠后缀加虚词过滤，会漏——比如「那家面馆」这种就没有后缀，抓不到。宁可漏，不要误报。
- 排序是贪心，不保证全局最优。
